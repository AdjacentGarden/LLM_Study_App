# 剩余风险与后续优化项

## 发布前仍需外部授权/环境输入

- 生产 PostgreSQL/pgvector migration 尚未执行，目标 DSN、备份与恢复演练需单独批准。
- 生产配置和流量切换尚未执行，必须显式启用 BGE-M3/CUDA；开发默认 hashing 不能被误当成生产 embedding。
- 生产历史课程清单不可从工作区推断，需获得生产快照的只读盘点授权；批量重解析仍是独立决策。

## 已知技术边界

- Office fallback 是安全的文本 SVG 预览，不保证 Word/PPT/Excel 原始版式的像素级还原。
- MinerU API 没有当前实现可依赖的取消接口；CloudPath 超时会停止等待并失效 generation，但上游 GPU 任务可能继续到完成/TTL 清理。
- MinerU 并发冻结为 1，能控制显存风险，但高峰吞吐依赖排队和容量规划。
- 图片在 MinerU 语义质量不足时进入真实 PaddleOCR；JP2/GIF 会先安全规范化为 PNG，增加少量磁盘和处理开销。
- 动画 GIF、多页 TIFF、旧版 `.doc/.ppt/.xls` 被有意拒绝，不是待修缺陷。
- DOCX 没有稳定渲染页码时只提供标题路径和块序号；兼容字段中的逻辑序号不能展示成“页”。

## 证据组合边界

- 阶段 5 的 13 格式真实流水线为避免访问数据库，RAG 使用显式 `artifact_fallback`；阶段 4 已在一次性隔离 PostgreSQL/pgvector 中独立验证真实 BGE-M3、1024 维、原子发布和检索一致性。生产 canary 仍需把“新格式 + 生产配置 pgvector”组合再验证一次。
- 默认全量测试跳过 9 个显式隔离库测试；这些测试已在阶段 4 隔离库独立 296/296 通过且清理为 0 行。若数据库、驱动或 migration 改变，必须重建新的隔离库复测。
- 阶段 0 基线使用无 MinerU endpoint、mock OCR 和 hashing，速度很快但语义检索不完整；不能把基线解析时间与新真实模型时间直接解释为性能退化。可比较的是质量提升以及新流水线是否满足冻结性能门槛。

## 后续优化

- 接入生产级 dashboards/alerts，并根据真实流量校准非冻结的队列运营告警。
- 在保持安全边界的前提下评估 Office 高保真预览服务。
- 为生产 canary 增加跨格式真实 pgvector/BGE-M3 查询集和容量测试。
- 获得授权后生成生产历史课程只读清单，再决定是否分批重解析。
- 若 MinerU 后续提供受信任取消 API，可增加上游任务取消和状态核对协议。

以上均已在部署门禁或回退手册中有对应控制；不影响当前代码与阶段 0 冻结验收通过，但在真正生产发布前不能忽略。
