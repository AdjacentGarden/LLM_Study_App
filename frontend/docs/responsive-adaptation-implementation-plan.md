# CloudPath 手机与 iPad 响应式改造执行方案

## 1. 目标与范围

本计划在 `frontend-update` 分支实施 CloudPath 前端响应式改造，使同一套 React 组件同时适配 iPhone 17 Pro 与 11 英寸 iPad Pro 的竖屏、横屏及 Safari 动态视口高度。

实施约束：

- 保留 React、TypeScript、Vite、现有 AppContext 和自定义 CSS。
- 不引入 Tailwind、shadcn 或新的 UI 组件框架。
- 不修改后端 API、请求结构、轮询逻辑或业务数据类型。
- 保留现有玻璃拟态视觉和手机端信息架构。
- 手机使用底部主导航；iPad 使用左侧 Navigation Rail。
- 所有阶段保留在工作区，最终封印审核通过后只创建一个本地提交。
- 不 push、不创建 PR，不处理用户添加的无关改动。
- Playwright/WebKit 模拟通过即满足设备验收，不等待实体设备。

### 1.1 目标视口

| 设备场景 | CSS 测试视口 |
| --- | --- |
| iPhone 17 Pro 竖屏，Safari 工具栏展开 | `402 × 681` |
| iPhone 17 Pro 竖屏，全屏/PWA | `402 × 874` |
| iPhone 17 Pro 横屏，Safari 工具栏展开 | `756 × 352` |
| iPhone 17 Pro 横屏，全屏 | `874 × 402` |
| iPad Pro 11 竖屏，浏览器视口 | `834 × 1194` |
| iPad Pro 11 竖屏，全屏 | `834 × 1210` |
| iPad Pro 11 横屏，浏览器视口 | `1194 × 834` |
| iPad Pro 11 横屏，全屏 | `1210 × 834` |

### 1.2 布局断点与短横屏规则

| 模式 | 宽度 | 行为 |
| --- | --- | --- |
| 手机 | `< 600px` | 单列、底部导航、底部 Sheet |
| 过渡 | `600–767px` | 增加间距，部分网格双列，继续使用底部导航 |
| 平板 | `768–1023px` 且高度 `≥ 600px` | 左侧 Navigation Rail、宽内容区、主从布局 |
| 宽平板 | `≥ 1024px` 且高度 `≥ 600px` | 左侧 Navigation Rail、双栏工作区、更多列网格 |
| 短横屏 | 任意宽度且高度 `< 600px` | 强制使用底部导航和紧凑单栏/横向滚动内容，不启用 Navigation Rail |

应用外壳的 Navigation Rail 唯一启用条件是 `(min-width: 768px) and (min-height: 600px)`；iPhone 的 `756 × 352` 和 `874 × 402` 横屏始终使用底部导航。媒体查询控制应用外壳；复杂页面优先使用容器查询，使组件按可用内容宽度而非设备名称响应。

边界测试必须覆盖：

- 宽度：`599/600`、`767/768`、`1023/1024px`，测试高度固定为 `800px`。
- 高度：`599/600px`，测试宽度固定为 `768px` 和 `1024px`。
- 全部 8 个目标视口均断言实际导航类型。

## 2. 子代理职责与审核协议

### 2.1 编码代理

- 任务名：`responsive_author`
- 模型：`gpt-5.6-terra`
- 思考深度：`max`
- 每次只实施主代理明确授权的当前阶段。
- 不提交、不 push、不进入下一阶段。
- 开始前必须阅读本文档和当前相关源码。
- 完成后必须报告：
  - 修改文件和实现内容；
  - 执行的检查命令及结果；
  - 已知限制；
  - `git diff --stat`。

### 2.2 审核代理

- 任务名：`responsive_reviewer`
- 模型：`gpt-5.6-sol`
- 思考深度：`max`
- 始终只读审核，不修改文件。
- 每次检查当前阶段需求、累积差异和既有阶段回归。
- 审核输出只能以以下结论之一开头：
  - `APPROVED`
  - `CHANGES_REQUESTED`
- 发现格式：
  - `[严重级别] 文件:行号 — 问题 — 期望修复 — 验证方式`
- 所有可执行问题必须修复；不阻塞的观察必须明确标记为 `NOTE`。

### 2.3 返修门禁

1. Terra 完成当前阶段并自测。
2. 主代理将当前阶段交给 Sol。
3. Sol 若返回 `CHANGES_REQUESTED`，主代理把全部意见交回 Terra。
4. Terra 完成修复并重新运行相关检查。
5. Sol 重新审核完整累积差异，而非只看修复行。
6. 只有 Sol 返回 `APPROVED` 后，主代理才更新审查记录并授权下一阶段。

### 2.4 审核门槛启用规则

始终适用的工程门槛：

- 当前阶段完整实现，没有越过后续阶段或引入无关修改。
- 阶段 0 只要求文档审查和对未跟踪文档执行直接尾随空白/文件结尾检查，不要求运行前端命令。普通 `git diff --check` 不得被当作未跟踪文件的验证证据。
- 从阶段 1 开始，`npm run lint`、`npm run test`、`npm run build` 必须通过。
- 从阶段 1 开始，当前阶段相关 Playwright 项目必须通过。
- 不使用 User-Agent 分支，不按物理像素布局。
- 没有新增的控制台错误、React 警告或 TypeScript 错误。
- 测试不存在固定延时、执行顺序依赖或外部网络依赖。

响应式门槛从其责任阶段开始累积适用：

- 阶段 1 只负责测试基础设施，不要求提前修复现有固定高度、触控尺寸或页面布局。
- 阶段 2 起，应用外壳、Header 和主导航必须满足动态高度、安全区、无水平溢出和导航触控尺寸要求。
- 阶段 3 起，浮层与 AI 助手必须满足焦点、键盘、触控和遮挡要求。
- 阶段 4–6 中，每个页面组从所属阶段开始满足无溢出、无遮挡、`44 × 44px` 关键触控目标和功能回归要求。
- 阶段 7 对全部页面、组件和目标视口执行统一最终门槛。

## 3. 重要内部接口变更

- 不修改后端或对外 API。
- 新增安全区、内容宽度、导航宽度、间距和触控尺寸 CSS variables。
- `.phone-shell` 更名为 `.app-shell`。
- `BottomNav` 更名为 `PrimaryNav`；保留 `active` 和 `go` props。
- `AppShell` 持有 `.app-shell` DOM ref，并把 ref 传给 `GlobalAIAssistant`；AI 定位不得继续使用字符串 DOM 查询。
- `ActionSheet` 不增加调用方必填参数；根据现有 `SheetState.type` 输出数据属性并响应式呈现。
- 新增 `responsive.css`，在 `base.css` 之后导入。
- 新增 Playwright 配置、响应式 fixtures、端到端测试和 npm scripts。

## 4. 实施阶段

### 阶段 0：建立执行文档

交付内容：

- 本文档。
- 设备矩阵、断点、阶段目标、实现约束、审核协议和审查记录。

代码审查标准：

- 计划与当前目录、组件结构和依赖一致。
- 所有高影响决策已锁定，编码代理无需自行决定断点、导航形态、文件组织或验收方式。
- 明确不修改后端、不引入新 UI 框架、不提前提交。
- 因本文档在阶段 0 尚未跟踪，使用 PowerShell 直接读取文件：`Select-String -Pattern '[ \t]+$'` 必须无匹配，原始文本必须以换行符结束；不得用普通 `git diff --check` 代替。
- Sol 输出 `APPROVED` 后才能启动阶段 1。

### 阶段 1：响应式测试基础设施

实现：

- 新增 Playwright 配置和稳定 API fixtures。
- 配置四个基础项目，并在各项目内执行配对视口和动态 resize：

| Playwright 项目 | 初始视口 | 配对视口 | 导航预期 |
| --- | --- | --- | --- |
| `iphone-17-pro` | `402 × 681` | `402 × 874` | 底部导航 |
| `iphone-17-pro-landscape` | `756 × 352` | `874 × 402` | 底部导航 |
| `ipad-pro-11` | `834 × 1194` | `834 × 1210` | Navigation Rail |
| `ipad-pro-11-landscape` | `1194 × 834` | `1210 × 834` | Navigation Rail |

- 增加 `test:e2e` 与 `test:responsive` scripts。
- 所有测试数据本地 mock，不依赖真实后端或外部网络。
- 本阶段只建立可通过的 smoke tests，不保存当前错误布局的视觉基线。
- `test:responsive` 只执行 `e2e/responsive.spec.ts`；测试能力按责任阶段逐步启用，不得在阶段 1 写入必然失败或跳过的未来断言。
- `test:e2e` 执行整个 `e2e` 目录，包含 responsive、流程和阶段 7 的视觉测试。

测试能力启用阶段：

| 测试能力 | 首次启用阶段 | 该阶段必须通过的内容 |
| --- | ---: | --- |
| 四项目启动、本地 fixtures、初始/配对尺寸加载 | 1 | 8 个尺寸均可加载应用；resize 后页面仍可交互，不断言尚未实现的导航或布局 |
| 导航类型、宽高断点、无水平溢出 | 2 | 8 个尺寸导航类型正确，所有宽高边界符合外壳规则 |
| 非零安全区 | 2 | 使用 style injection 覆盖 CSS 变量为 `top:47px`、`bottom:34px`、左右非零值并验证外壳 |
| 浮层、焦点、软件键盘、AI resize | 3 | ActionSheet、Toast、AI 面板和输入框在动态可视高度下正确 |
| 页面组功能与布局 | 4–6 | 只启用当前阶段所属页面断言，并保留已批准阶段回归 |
| 视觉基线、全部触控和可访问性 | 7 | 对完整页面矩阵统一启用 |

动态视口测试使用 `page.setViewportSize` 在每个项目的初始视口与配对视口之间往返。阶段 1 只断言应用仍可加载和交互；阶段 2 起再断言导航和布局。

软件键盘模拟在阶段 3 启用：

- iPhone 使用 `402 × 430` 的缩高 viewport，并保持底部导航。
- iPad 保持 `834 × 1194` 布局 viewport，使用 `addInitScript` 安装测试专用 `visualViewport` shim，把可视高度从 `1194px` 改为 `760px` 并派发 `resize`；Navigation Rail 必须保持不变。
- 恢复可视高度后再次断言浮层位置。生产代码不得包含测试分支。

代码审查标准：

- 四个设备项目均能启动并加载应用。
- 阶段 1 的 Playwright 列表和结果只需证明 8 个固定尺寸、配对 resize、fixtures 与页面加载实际执行；安全区、键盘和断点断言分别在阶段 2、3 启用。
- fixtures 可重复，无固定延时、外部网络和执行顺序依赖。
- 失败信息能定位设备、页面和断言。
- 没有为了测试通过而弱化业务逻辑。
- 原有 Vitest 测试全部通过。
- Playwright 浏览器安装与测试产物不污染 Git 差异。

### 阶段 2：安全区、应用外壳与主导航

实现：

- `viewport` 增加 `viewport-fit=cover`。
- 设计令牌增加：
  - 安全区变量；
  - `--app-max-width: 1210px`；
  - `--content-max-width: 1120px`；
  - `--reading-max-width: 720px`；
  - `--nav-rail-width: 88px`；
  - 自适应水平间距、布局间距和 `44px` 触控下限。
- 新增并末尾导入 `responsive.css`。
- `.phone-shell` 更名为 `.app-shell`，使用完整设备宽度和 `100dvh`。
- 同阶段同步更新所有 JSX、CSS 和运行时引用；`AppShell` 创建容器 ref 并传给 `GlobalAIAssistant`，替代 `document.querySelector(".phone-shell")`。
- 删除模拟状态栏，顶部空间改由安全区控制。
- `BottomNav` 更名为 `PrimaryNav`：
  - 手机为底部导航；
  - iPad 为左侧 Navigation Rail。
- 内容容器启用 container query。
- iPad 内容最大宽度 `1120px`，正文阅读宽度不超过 `720px`。
- 在宽度不超过 `1210px` 的触控设备上，`.app-shell` 使用完整 viewport 宽度；在 `1210 × 834` 下宽度必须为 `1210px`。仅在宽于 `1210px` 且具有精确指针的桌面预览环境中居中显示最大宽度 `1210px` 的外壳。

代码审查标准：

- 全部目标尺寸无水平滚动。
- iPhone 不再依赖 `760px/874px` 固定或最小高度。
- iPad 不再显示 402px 手机框。
- `rg "phone-shell" frontend/src` 不得存在 JSX、CSS 或运行时遗留引用。
- 阶段 2 验证 AI 图标在改名后仍可拖动、约束和吸附。
- 手机与 iPad 使用同一导航组件和同一导航数据。
- Header、内容和导航正确避让四个安全区。
- `hideNav` 行为不变。
- `599/600px`、`767/768px`、`1023/1024px` 宽度边界及 `599/600px` 高度边界无重叠或异常跳动。
- `1210 × 834` 下 `.app-shell` 全宽、左右位置和内部安全区 padding 符合定义。
- CSS 以移动优先组织，响应式覆盖集中且可维护。

### 阶段 3：全局浮层与 AI 助手

实现：

- ActionSheet 根据 `sheet.type` 输出数据属性：
  - 手机统一为底部 Sheet；
  - iPad chat 为右侧面板；
  - source 为宽对话框；
  - note/editChapter 为居中对话框。
- Toast 手机避开底部导航，iPad 位于内容区右下角。
- AI 助手取消固定 `top: 600px`。
- 使用容器尺寸、`ResizeObserver`、`visualViewport` 和横竖屏事件重新约束 AI 图标与面板。
- 手机 AI 对话使用全屏或底部模式；iPad 使用右侧面板。
- 加入 Dialog 语义、焦点锁定、Esc 关闭、关闭后焦点恢复和软件键盘适配。

代码审查标准：

- 浮层不超出 viewport，不被导航或安全区覆盖。
- Tab 焦点不会离开打开的对话框。
- Esc 关闭后焦点返回原触发控件。
- 拖动 AI 图标并旋转设备后仍处于可见范围。
- 软件键盘出现时输入框和发送按钮保持可见。
- reduced-motion 模式无强制入场或拖动动画。
- 所有关闭按钮具备可访问名称和足够触控尺寸。

### 阶段 4：教材上传与课程生成流程

覆盖上传、解析准备、处理进度、目录确认和生成成功页面。

实现：

- 手机保持单列任务流程。
- iPad 使用“主操作 + 支持信息/状态”双栏。
- 目录确认：
  - 手机保留章节卡片和底部编辑 Sheet；
  - iPad 使用左侧章节树、右侧证据与编辑区；
  - 确认操作使用 Sticky Action Bar。
- 处理进度、异常和重试状态在两种设备上均清晰可见。
- 保持所有后端调用、轮询和错误处理行为不变。

代码审查标准：

- 上传、解析、编辑、删除、确认和课程生成可完整操作。
- iPad 切换章节不丢失本地修改。
- 长文件名、长章节名、失败消息和 0–100% 进度不溢出。
- Sticky Action Bar 不遮挡最后一项。
- 空状态、失败状态和后台运行状态均适配。
- API 请求数量、轮询间隔和错误逻辑无非必要变化。

### 阶段 5：首页、课程库与章节学习

覆盖首页、课程库、课程主页、章节学习和原文阅读。

实现：

- 首页 iPad 使用“今日任务 + 当前课程”双栏，快捷入口扩展为四列。
- 课程库手机一列、iPad 竖屏两列、横屏三列。
- 章节学习手机保持顺序阅读，iPad 使用主阅读区和 Sticky 学习工具栏。
- 原文阅读在 iPad 使用更宽文档画布和页码/操作侧区。
- 图片使用稳定 `aspect-ratio`、`object-fit` 和最大尺寸。
- 正文控制在适宜行宽，避免横屏超长文本行。

代码审查标准：

- 首页主任务在所有尺寸位于主要首屏区域。
- 课程网格无拉伸、错位和明显高度抖动。
- Lesson 的引用、插图、AI、闪卡、练习和完成入口全部可用。
- SourceReader 页码切换和返回路径正确。
- iPad Sticky 工具栏不覆盖正文或底部内容。
- 图片失败 fallback 尺寸稳定，无布局跳变。

### 阶段 6：学习工具与其余页面

覆盖学习计划、闪卡、作业、诊断、错题、笔记、报告、个人中心、社区和导出。

实现：

- 学习计划：iPad 左侧日期/日历，右侧当天任务。
- 闪卡：中央卡片与侧边掌握度/来源信息。
- 作业：题目/引用与作答区双栏。
- 诊断：结果与知识点/下一步双栏。
- 错题、笔记使用列表与详情自适应布局。
- 社区手机一列，iPad 两至三列。
- 报告、个人中心和导出使用合适宽度与网格。
- 保持社区、导出等现有 mock 行为，不扩展业务能力。

代码审查标准：

- 所有剩余页面在四个设备项目中可访问且无溢出。
- 日历七列在 402px 宽度下可读、可点。
- 作答输入在软件键盘和横屏短高度下可用。
- 闪卡翻面、提交诊断、错题筛选和计划更新行为不变。
- Mock 页面没有被改为虚假后端调用。
- 空、加载和错误状态均完成响应式检查。

### 阶段 7：最终响应式验收与终审

实现：

- 为核心页面和浮层建立稳定视觉截图基线。
- 增加断点边界、水平溢出、44px 触控目标、导航遮挡和安全区断言。
- 测试文字放大、reduced-motion、键盘导航和横竖屏切换。
- 清理重复或失效的固定手机样式。
- 更新本文档审查记录和最终结果，并执行封印审核流程。

最终必跑：

```powershell
npm run lint
npm run test
npm run build
npm run test:responsive
npm run test:e2e
git diff --check
```

代码审查标准：

- 四个主要项目和全部边界尺寸通过。
- 核心页面视觉截图无非预期差异。
- 所有页面无水平滚动、遮挡、不可见主操作或小于 44px 的关键触控目标。
- 没有未解决的 Sol 审核意见。
- Git 差异仅包含本文档、前端响应式实现和测试。
- Terra 完成阶段 7 后，主代理先把测试结果写入审查记录并标记“待终审”。
