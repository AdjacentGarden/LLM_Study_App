# BookCourse AI 前端结构优化方案与评估标准

## 1. 优化目标

本轮优化把原型从“功能页面集合”收敛为 PRD 所要求的“书籍课程化学习闭环”。核心路径为：

首页今日任务 -> 上传书籍 -> 章节保真确认 -> 我的课程 -> 章节学习 -> 闪卡记忆/作业练习 -> 作业诊断 -> 错题复习/计划调整 -> 导学笔记导出

一级导航保持 PRD 指定的 4 项：首页、社区、上传、我的。书库/我的课程、闪卡、错题、笔记、计划都作为课程空间内的二级能力，不新增到底部导航。

## 2. 前端信息架构

### 一级入口

- 首页：只回答“今天下一步学什么”，展示继续学习、待复习闪卡、计划调整和核心快捷入口。
- 社区：发现课程包，导入后进入同一课程空间。
- 上传：从本地教材生成课程，重点展示章节保真映射。
- 我的：用户学习数据、课程入口、导出记录和偏好。

### 二级课程空间

- 我的课程：课程资产列表，展示进度、计划天数、错题数、闪卡复习量。
- 课程主页：课程中枢，包含学习计划、章节目录、错题本、导学笔记、知识点闪卡入口。
- 学习计划：每天任务，并展示因错题和闪卡表现触发的计划调整。
- 章节学习：按“来源依据 -> AI 导学 -> 学习行动”分层。
- 知识点闪卡：新增 focused screen，用于本节概念、错题薄弱点和今日待复习卡片。
- 作业诊断：呈现做对部分、知识卡点、原书页码、提示、再试一次和加入复习计划。
- 错题本：错题、错因、原书页码、关联知识点、闪卡巩固和计划联动。
- 导学笔记：聚合笔记，并支持从笔记生成闪卡和导出 PDF。

## 3. 闪卡功能入口策略

### P0 入口

- 课程主页：`知识点闪卡`，作为本课程的主入口。
- 章节学习页：`练本节闪卡`，用于学完马上背。
- 错题本：`用闪卡巩固`，用于薄弱点复习。
- 首页今日任务：`今日待复习闪卡`，进入当天复习队列。

### P1 入口

- 学习计划：作为任务类型出现，例如“错题知识点闪卡复习 · 10 分钟”。
- 导学笔记：`从笔记生成闪卡`。
- 社区课程详情：展示“包含闪卡数量”，导入后进入课程空间使用。

## 4. 实现范围

### 文件调整

- `src/types/app.ts`：新增 `flashcards` screen。
- `src/App.tsx`：新增闪卡页面标题和 render 分支；优化“书库”为“我的课程”。
- `src/data/mockBook.ts`：补充闪卡、生成模块、计划调整、课程资产等 mock 数据。

- `src/styles/base.css`：补充课程空间、章节映射、闪卡、计划调整、诊断闭环样式。

## 5. 评估标准

### IA 与 PRD 对齐

- 底部导航必须只有：首页、社区、上传、我的。
- 原型必须能表达“上传一本书生成课程”的主线。
- 上传流程必须突出原书目录与 AI 课程目录映射。
- 课程主页必须成为二级课程空间中枢。
- 闪卡不得变成独立一级导航，必须归属于课程/章节/错题/计划。

### 学习闭环

- 首页必须展示下一步学习和今日待复习闪卡。
- 章节学习页必须包含来源页码、AI 导学和学习行动。
- 作业诊断必须包含卡点、来源页码、提示和复习计划联动。
- 错题本必须能进入闪卡巩固。
- 学习计划必须展示动态调整记录。

### 闪卡体验

- 至少有一个独立 `flashcards` screen。
- 课程主页、章节页、错题本、首页必须有进入闪卡的入口。
- 闪卡页必须展示复习队列、当前卡片、记忆操作和来源章节。
- 闪卡内容必须和当前教材知识点相关，而不是泛化卡片。

### 前端质量

- TypeScript 构建必须通过 `npm run build`。
- 不引入新依赖。
- 不重命名既有主要 screen，避免破坏现有状态机。
- 移动端卡片不应明显溢出、重叠或遮挡底部操作。
- 样式应沿用现有 iOS/液态玻璃/课程卡片视觉，不引入突兀的新设计体系。

### opencode 评估通过标准

- 使用本文件作为评估依据调用 `opencode`。
- 若 opencode 给出优化建议，按建议继续修改。
- 重复评估，直到 opencode 不再给出需要执行的优化建议，或明确反馈无需进一步修改。
