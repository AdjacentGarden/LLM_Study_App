# 原生客户端 P0 后端接入

当前原生工程位于本仓库 `frontend/`，接入同仓库 `backend/` 的 FastAPI 服务；迁移来源及验收见 [迁移说明](../../docs/SWIFTUI_MIGRATION.md)。原有页面、组件、课程成功动画、阅读器和离线 fixtures 保留；普通启动进入账号模式，`--fixture` 继续使用隔离的离线数据。

## 当前局域网部署与后台任务

App 默认连接 Windows 网关 `http://10.249.44.137:8100`，由网关转发到 Linux 业务服务。使用同局域网或 VPN；VPN 地址可在登录页「学习服务地址」填 `http://100.86.143.88:8100`。服务地址保留在本机，真实认证和所有业务仍在后端。下面的本机开发方式需要显式改成回环地址。

OCR 后通过 `/api/books/{id}/prepare` 查询完整教材准备任务，目录、索引和当前诊断题均就绪后才继续。课程生成通过 `/api/interviews/{id}/course-jobs` 提交与查询，提交前将请求编号持久保存到本机 SQLite；离开页面停止本机查询，服务器任务继续。重新打开本章恢复原请求。失败任务普通查询不会重新生成，只有明确点击「重新生成课程」才发起一次重试；旧收据保留，后端仍检查次数上限与服务冷却。

Info.plist 声明局域网和麦克风用途，并为上述两个服务 IP 与开发回环 IP 配置精确 HTTP 例外。当前 Mac 缺少完整 Xcode/iOS SDK，主机上的 Core 类型检查和合同回归不能代替真机安装、系统权限或网络路由验收。

## 本地启动

1. 在后端使用 Python 3.11+ 创建 `.venv`，安装 `pip install -e ".[dev,pdf]"`。
2. 在 `LLM_Study_App/backend` 运行 `./scripts/run_native_dev.sh`，默认监听 `http://127.0.0.1:8100`，开启本机默认账号。此时无需 `.env`、SMTP 或 OCR 模型。App 自动登录后，首次展示称呼、学习目标、每日时间、学习卡点、帮助方式、计划支持六步个性化问题；完成后进入首页，重启后保留同一个账号和偏好。
3. Xcode 打开本原生工程运行。在本机 scheme 显式设置 `BOOKCOURSE_API_BASE_URL=http://127.0.0.1:8100`；登录页的「学习服务地址」也可切换后端。

当前未安装 OCR 时，仍可上传并保存 PDF；点击处理会提示“教材解析服务尚未启动”，保留文件和草稿。目录生成、课程生成和教材答疑需要后续配置模型服务，不会自动显示演示答案。

准备接入模型时，再安装 `.[rag]` 依赖，将 `LLM_Study_App/.env.example` 复制为 `LLM_Study_App/backend/.env`，按本机环境配置：
   - `APP_DATA_DIR`：教材、任务、索引与数据库所在目录。
   - `OCR_WORKER_ENABLED=true`，以及可执行的 MinerU/OCR 环境；默认模板关闭 worker，客户端会明确报告解析服务未启动。
   - 文本模型提供方、服务地址和服务端密钥；目录与诊断使用该服务。
   - `RAG_EMBEDDING_MODEL_PATH`、`RAG_RERANKER_MODEL_PATH` 和相应模型权重。新上传教材不需要预先登记进发布清单，也不要求已存在一个主教材索引。
   - 恢复邮箱登录时配置 SMTP，并用 `NATIVE_LOCAL_LOGIN_ENABLED=0 ./scripts/run_native_dev.sh` 启动。仅隔离测试使用 `.test` 演示验证码。

默认账号仅限本机回环访问，并要求 `APP_ENV` 为 `development` 或 `local`。泛用 uvicorn 启动默认关闭该功能；本地开发脚本默认开启。局域网真机或远程部署需切回正式认证，或使用安全的本机转发方案。

服务端密钥不进入 App。普通账号模式的三个答疑入口对在线教材调用自己的 FastAPI 后端；尚未上传的本机教材使用明确标记的离线原文检索；本机 DeepSeek key 只供原有离线/个人调试路径使用。

## 已接入流程

本地默认账号自动进入（也保留可切回的邮箱登录/注册）→ 选择 PDF → 上传并绑定身份 → 服务端 OCR → 生成目录与检索索引 → 原生六步课程设置 → 确认个人目录 → 服务端真实诊断与画像确认 → 生成首章课程 → 原有成功动画 → 学习。

登录和个性化设置是独立状态。首次默认登录不会以服务器预设昵称、目标或旧缓存判定为已完成引导；偏好通过 `/api/native/learner-preferences` 保存，并同步昵称。原生引导草稿按后端及账号隔离，个人页修改偏好也写入后端。

## 六步个性化引导（已实现）

| 步骤 | 问题 | 答案 |
| --- | --- | --- |
| 称呼 | 我们怎么称呼你？ | 姓名或昵称，必填，最多 30 字 |
| 学习目标 | 你希望通过学习收获什么？ | 系统掌握知识、备考提升成绩、提升实际能力、探索兴趣内容；单选 |
| 每日时间 | 你每天可以投入多少学习时间？ | 30 分钟以内、30–60 分钟、1–2 小时、2 小时以上；单选 |
| 学习卡点 | 学习时，你最想改善什么？ | 更容易开始、更专注投入、更深入理解、更牢固记忆；最多两项 |
| 帮助方式 | 你更喜欢怎样的学习引导？ | 抓住重点、讲透原理、结合示例、循序展开；最多两项 |
| 计划支持 | 你希望怎样安排学习节奏？ | 自主安排、共同规划、提供完整计划、先自由体验；单选 |

除称呼外均可跳过。沿用原有贴纸图标、双列选项卡、紫色主按钮和页面切换动画；支持返回修改、逐项草稿恢复和保存失败重试。提交成功后才清除草稿并进入首页。个人页可编辑全部偏好，设置页可查看。

扩展 `LearnerPreferences` 字段：`learningBarriers`、`guidanceStyles`、`planningSupport`、`onboardingVersion`。新版完成时写入 `onboardingVersion: 2`；旧版三个字段仍可解码，缺少版本按 1 处理。旧账号自动从第 4 步补充，保留姓名、目标、时间、课程和进度。旧版未完成草稿保留原步骤；旧客户端修改原字段时，后端保留新增答案和完成版本。新字段枚举、最多两项和禁止重复由后端校验。

## 答案影响课程设计的后续修改方案

后端已完成统一配置、课程单元、完整知识队列、每日计划、答疑偏好和可撤销调整建议，见 [同仓库后端接口](../../docs/NATIVE_CLIENT_P0.md) 的“六步答案驱动课程设计”。现有前端的六步采集、编辑、保存和恢复保持兼容，`CourseRecommendations` 仍负责旧版今日建议。下面的路线已完成后端部分；新单元、后端每日计划和建议确认/撤销界面还需要 SwiftUI 接入。

1. **统一有效配置。** 在后端增加 `LearningDesignConfig` 及确定性解析函数，合并账号默认偏好与 `native_workspaces.preferences` 的课程专属覆盖；当次明确要求优先。知识掌握证据单独保留在 `assessment.models.LearnerProfile`，不以时间多少或卡点答案推断能力。课程设置展示继承项及修改入口，避免重复询问已经确定的偏好。
2. **先接每日任务。** 扩展 `CourseRecommendations` 和服务端任务计划，依据每日时间安排预计用时和可完成的学习段落；“更容易开始”先提供明确的小任务，“更专注投入”一次聚焦一个目标，“更牢固记忆”增加回忆任务。完成记录继续使用稳定章节、知识点和任务标识，不因偏好变更清零。自主安排提供候选任务，共同规划允许确认及调整，完整计划提供每日清单，自由体验提供轻量下一步建议；提醒单独由用户开启。
3. **接课程编排和阅读。** 在 `personalization.policy.PersonalizationPolicy`、`generator.ChapterCourseCompiler` 与 `Core/CloudMapping.swift` 中传递有效配置，给知识单元增加目标、前置知识、预计用时、讲解区块和检查题。重点偏好先给框架，原理偏好展开推导，示例偏好增加有教材依据的案例，循序展开按步骤组织。知识内容、章节完整性和引用校验仍由教材约束，细分后的未学内容保持可访问。偏好进入编排缓存指纹，课程保存配置快照和版本；只影响之后的内容或经用户确认的新版本。已有生物课程先增加个人任务与展示顺序，保持共享教材和原文证据。
4. **接统一答疑。** `Core/CloudStore.answerAssistant` 已改用当前工作区与资料的 QA 接口，并传入章节、最近最多 8 条对话和课程资料范围；后端校验资料归属、读取对应偏好，引用保留各自教材 ID。历史对话只帮助理解问题，不作为教材证据。用户明确说“直接给答案”等当次要求优先。卡点支持影响解释和检查方式，不改变事实和引用。
5. **加入反馈调整。** 复用答题结果、错误知识点、闪卡复习和完成记录，建议补前置概念、增加示例或调整未来任务量。先展示可撤销建议；连续证据支持后再调整，不根据一次停留或答错重设能力。记录每次调整原因和配置版本，保留用户手动修改入口。

验收应覆盖：同一本教材两套偏好产生可见的任务和讲解差异；每门课可独立覆盖；跳过时有默认行为；更改偏好保留学习进度；引用和知识覆盖不丢失。真实生成与答疑还需配置 OCR、向量/重排和文本模型服务，当前可先用已有生物课程验证任务计划和界面呈现。

## 发现中的已有生物课程

“发现”从后端目录加载《遗传与进化高频考点课》，源内容为原项目已导出的《生物 必修2 遗传与进化》：15 个课时、90 张闪卡、45 道练习。用户选择课程并完成原有六步偏好设置后，即可导入自己的工作区；不要求重新 OCR 或调用课程生成模型。

目录和课程来自后端打包快照 `native_biology.json`，记录原导出数据 SHA-256。App 只展示后端目录，按课程 ID 去重；空目录或连接失败不会加载本地备用书单，删除个人课程不会自动加入其他教材。原生端继续使用已提交的封面、配图和 125 张原文页图片，不声称存在一个可下载的原 PDF。保留原有章节树、课时状态、AI 补充内容及待核验标记；不为缺失的教材内容补造原文证据。

导入不带入演示账号的进度和掌握度。工作区及资料 ID 独立，计划任务从待学习开始；进度、最后阅读位置和客观题提交保存在后端，重复导入请求按稳定工作区 ID 恢复。公开题目清空答案，客观题在服务端评分；主观题评分和教材答疑仍需要模型服务。在线发现不显示虚构评论或模拟学习人数。

其他章节在首次进入时按需生成。生成前的章节只有目录信息，不伪装成已经生成的教学内容。练习公开模型不包含答案；提交和评分通过后端完成。教材问答返回原文引用，点击后使用受保护的 PDF 下载接口及 PDFKit 定位。

上传/解析失败保留原 PDF 和课程草稿。重启后通过已保存的书籍标识继续查询；准备或课程任务失败需用户明确重试，不因打开页面而重复调用生成模型。

## 数据与隔离

- `workspace_id` 是多资料课程容器；`resource_id` 代表课程中的一份教材；`session_id` 是该资料的诊断档案；`course_id` 是生成的一章教学内容。
- 同一本书可以加入不同课程，目录、诊断和进度相互隔离。原生视图仍使用已有模型，`CloudMapping` 负责适配。
- SQLite 的云端缓存按后端地址和账号 ID 隔离，不加载内置演示教材。PDF 附件映射、待同步进度和未完成草稿一并保存。
- 页码、章节、课时、完成状态、任务状态和本机掌握标记进入进度队列。队列先落盘，使用版本号与稳定 mutation ID 上传；重复写入不会重复增加版本，并发冲突先读取服务器版本再合并完成记录。掌握标记在本机按资料 ID 隔离，按明确的新增／取消操作合并，保留其他设备对不同卡片的修改。旧缓存从各资料的进度恢复，避免把教材级集合复制到多门课程。
- 凭证在真机写入 Keychain，按后端地址隔离。无签名 Debug Simulator 使用应用私有目录中的受保护文件作为开发回退，不写入 SQLite 或仓库。退出撤销服务器会话并清除当前凭证。
- 闪卡“记住了／还不熟”分别记录 `good/again` 复习事件。生成课程调用原 FSRS 接口；内置课程调用资料级 `catalog-flashcards` 接口。事件先写入账号缓存，断线及重启重试沿用同一 `event_id`；服务端返回的复习时间经 bootstrap 恢复。最后一张也可使用现有评分按钮，“完成记忆”本身不增加掌握度。
- 本次保留笔记的本机体验，并将本机笔记缓存按账号隔离。笔记保存等待 SQLite 的实际写入结果，失败会抛回编辑器以保留草稿和重试入口。手写/语音识别与整理调用真实 Studio 任务，保留本机原稿；跨设备原稿同步、原生好友页面和真实积分计费仍未接入。详细真实边界见 [功能边界](FEATURE_BOUNDARIES.md)。

## P2 缓存与能力契约

启动、离线身份恢复与鉴权重试位于 `Core/CloudBootstrap.swift`；按版本获取正文位于 `Core/CloudContent.swift`。原生请求 `/api/native/bootstrap?mode=metadata`，已缓存的内置正文跨个人课程复用，私人正文仍按账号隔离。SQLite 将不可变正文、资源进度、笔记与轻量应用状态分开；读取兼容旧单快照。旧 URL 的尾斜杠及默认端口凭证/缓存可迁移，不同非默认端口不会互相恢复。

网络传输失败时，已有验证身份可以恢复本机学习、笔记和待同步操作；401、`auth/me` 的空账号、bootstrap 的 401 均清除当前界面及凭证，不通过离线缓存绕过。服务或账号切换不展示其他缓存；恢复网络先重新验证同一账号，再刷新并同步。升级前未保存过验证身份的客户端，需要一次联网鉴权建立该身份记录，之后可离线重启。

后端已具备但原生尚未接入的教学单元、计划调整、笔记云同步、转写、手写识别与社区/社交见 [能力矩阵](../../docs/NATIVE_CAPABILITIES.md)。这些能力不因为后端接口存在而自动显示为原生可用。
