## RAG 并发门禁

首次 4 并发冷启动测试发现 4/4 返回 503。根因是 `functools.lru_cache` 在并发首次调用时可能重复执行底层构建，多个服务实例同时导入 Transformer 并把同一模型搬到 GPU，触发导入竞态和 meta tensor 错误。

修复：

1. 使用双重检查的进程级互斥锁构建唯一 RAG 服务实例。
2. 在 FastAPI lifespan 中预热 embedding 和 reranker，预热成功前不开放健康端口。
3. `/api/rag/health` 从“只检查配置”升级为检查真实 `ready` 状态。
4. 启动健康等待从 10 秒扩展到 30 秒。
5. 新增 20 线程、40 次并发冷启动测试，断言只创建一个服务。

修复后：

- 4 并发同题：4/4 HTTP 200、4/4 supported、页码均为 47/48/49、claims 全部非空、检索 171–440 ms。
- 8 并发混合：8/8 HTTP 200；4/4 书内题 supported；4/4 书外题 insufficient 且 claim 数为 0。
- 最终冷重启后单题：HTTP 200、置信度 0.95、5 个 claims、证据页 47/48/49、检索 119 ms。
