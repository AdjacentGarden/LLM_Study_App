# 模块 3：通用章节结构与证据化摘要

## 目标

把任意书籍的高质量 OCR 文本重建为稳定的“章”级结构，并生成整书摘要、章节摘要和知识点。算法不能依赖生物学术语，也不能把目录、页眉或缺失正文的目录条目误当成真实章节。

## 边界识别

- 支持中文“第 N 章/篇/部”、英文 `Chapter N`、`Part/Book N` 和罗马数字。
- 目录页由“目录/Contents”标签或单页多个章标题识别，只作为候选来源。
- 正文标题结合标题层级、顶部坐标、块类型和长度打分。
- 同一章在页眉页脚重复出现时只保留正文标题。
- 同时存在 Part 和 Chapter 时选择更细且稳定的 Chapter 层，不输出混合嵌套层级。
- 区间必须连续、无重叠、不越界，章节 ID 由标题和起始页稳定散列产生。
- 没有明确章节的书诚实退化成“全书内容”一章，不伪造结构。

## 摘要与证据协议

后端先把每章原文切成不超过 480 字的连续证据单元。切片只寻找原字符串中的标点边界，不插入、删除或改写字符。模型只能选择后端给出的内部证据编号：

- 章节摘要至少选择 2 条证据；
- 每个知识点必须选择自己的证据；
- 未知编号、缺失证据、非法 JSON 和未覆盖章节会被拒绝并重试；
- 最终面向用户只返回页码与原文，不展示内部编号；
- 整书摘要只能综合所有已核验章节摘要，并必须覆盖每个章节 ID。

## 持久化 API

- `POST /api/books/{book_id}/structure`：只允许 OCR 已通过质量门控的书生成结构。
- `GET /api/books/{book_id}/structure`：读取 SQLite 中持久化的结构。
- 生成成功后书籍状态进入 `structured`；重复调用 OCR 入口不会把状态倒退。
- 服务重启后返回的结构 JSON 与重启前逐字节一致。

## 验证门禁

- 71 项后端测试全部通过，Ruff 与 MyPy strict 通过，前端 TypeScript/Vite 构建通过。
- 覆盖中文目录去重、页脚重复、英文 Chapter、Part/Chapter 层级选择、无章节回退、稳定 ID、非法证据重试、未知章节拒绝和 API 持久化。
- 真实 125 页扫描教材检测 6 个正文章节，边界为 10-35、36-55、56-73、74-91、92-103、104-125。
- 目录中存在但正文缺失的“第 1 章”没有被伪造；重复章名没有制造额外边界。
- DeepSeek 真实生成 6 个章节摘要、67 个知识点；67/67 知识点均有证据。
- 章节摘要与知识点合计 168 条引用，168/168 都是对应 PDF 页文本的连续逐字子串，确定性证据准确率 100%。
- 完整结构通过规则评估报告，错误数 0。
- 3 页真实上传书通过正式 API 生成并持久化；后端重启前后响应 SHA-256 一致。

## 外部依赖状态

PUCODING 当前返回 `insufficient_quota`，因此本模块没有声称完成跨模型评审。现有门禁为 DeepSeek 结构化生成加后端确定性边界/证据校验；PUCODING 恢复额度后可追加独立语义评审，但不会替代现有硬校验。
