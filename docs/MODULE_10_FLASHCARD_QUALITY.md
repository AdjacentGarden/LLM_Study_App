# 闪卡全文编辑与发布审校

## 问题与修复

原课程编译器把知识点按“是、包括、通过”等词切开，再硬截取 24 字作为问题主题。
例如“摩尔根通过果蝇……”会变成“请解释摩尔根”。背面则直接复制知识点文本，
导致 OCR 残留错误未经检查就进入闪卡。

编译器现在保留完整草稿，不再按动词或字数截断。正式返回课程之前必须经过
`FlashcardQualityGate`，不论课程是新生成的、POST 命中旧版本，还是 GET 读取历史版本。

## 强制流程

1. 输入章节名称、教学难度、完整知识点、逐卡原文证据（页码与引用）。
2. DeepSeek 重新编辑正反面：明确实验对象、完整概念、问答对应，纠正断字和标点。
3. 第二次独立请求审校。逐张检查完整性、可读性、原文支持、条件与科学符号。
4. 服务端核验结构：所有卡片覆盖且不重复、ID 一致、严格布尔审查状态、无乱码或控制字符。
5. 拒绝时带具体意见重写并重新审校，最多两轮；仍失败返回 503，禁止退回未审草稿。
6. 只缓存审校通过的结果。缓存键涵盖全文知识点、引用、章节、难度、模型及提示词版本。

对原文 OCR 本身残缺的公式、上下标，不凭空补符号，也不机械照抄成错误公式。
可用可靠的自然语言关系表达时改用文字；无法取得依据时拒绝通过。
原始引用不会被大模型重写，以保留可核查来源。

## 缓存、兼容与运行

- 缓存位于服务器数据盘 `data/state/flashcard_quality.sqlite3`，保留最终审校结论和时间。
- 卡片 ID、知识点 ID、个人推荐理由、引用、课程版本及复习事件保持不变；仅更新问答文案。
- 相同证据与难度的文案可复用，用户个人历史不进入共享缓存。
- 每批最多 8 卡；同章节同难度请求串行去重，模型请求最多两路并发。
- 审校调用超时为 120 秒，网络层保留现有一次重试。
- 4090 可直接访问模型接口；启动脚本不再默认依赖本机的 17897 反向代理。
  如确有需要，仍可在服务器环境中显式设置代理。

## 历史迁移与回滚

`backend/scripts/review_existing_flashcards.py --report-dir <服务器报告目录>`
读取部署环境中的凭据，不输出密钥。开始前通过 SQLite backup API 创建一致性备份。
逐课程审校，保存前后文案、原文证据与失败意见。失败课程不覆盖，运行返回非零状态，
API 也不会将未通过的文案作为成功课程返回。

回滚代码不需要回滚学习历史。数据库备份仅作审计和必要时的恢复依据，
不得直接覆盖迁移后产生的新复习记录。

## 验证范围

新增测试覆盖姓名截断、乱码、异常断字、合法公式、遗漏/重复 ID、非布尔审查结果、
拒绝后重试、模型失联、证据缺失、缓存复用与失效、跨用户 ID 保留，
以及新课程、缓存 POST、历史 GET 的强制审校与失败不发布。

注意：两次模型调用提供编辑和复核，不等于两个不同模型一致，也不构成零错误保证。
严格门禁会增加首次生成耗时；对证据本身不可靠的内容，宁可提示重试或待核查，不能伪造正确性。
