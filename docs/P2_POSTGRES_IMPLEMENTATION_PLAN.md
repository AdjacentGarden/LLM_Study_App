# P2 与 PostgreSQL 第 1–4 阶段实施计划

日期：2026-10-22。范围依据本轮 main 审查的 P2 第 7–10 项及 PostgreSQL 接入评估。保留当前未提交的 P1 修复。用户明确放弃 Redis，本轮移除活动部署对 Redis 的依赖，不引入 Redis、消息代理或向量数据库迁移。

## 约束与交付

- 保持已有界面、功能、HTTP 字段、身份 ID、错误语义、revision 和幂等 ID 兼容；保留 iOS SQLite 与离线数据。
- 服务端 PostgreSQL 为可选择的主存储；未配置连接时保留 SQLite 开发/测试路径。不得配置 PostgreSQL 失败后静默回退 SQLite。
- PDF、OCR 图片、模型与索引保留文件存储；说明多机部署需要共享产物与一致的账户签名密钥。
- 不改写用户现有数据、不执行正式部署或生产切换。阶段 4 交付迁移工具、运行手册及隔离迁移演练结果。
- 一个 GPT-6.1-sol / high 子代理负责实施；主代理独立执行测试、检查差异、审核并修复发现的问题。

## P2-7：离线冷启动

以最近验证成功的账户身份和规范化服务地址隔离缓存。网络暂时失败时允许恢复已有学习空间及现有离线操作，待恢复网络后重试同步。明确的 401/会话失效不能当作网络故障绕过。注销、切换账户和服务不得泄漏旧缓存。回归覆盖离线重启、401、账户/地址切换及恢复同步；不更改现有页面布局。

## P2-8：启动与持久化体积

增加兼容的轻量 bootstrap 协议，元数据与正文分离，正文按需加载，公共内置内容按版本复用，个人进度独立持久化。旧客户端默认响应保持兼容，原生端使用轻量模式且处理缓存缺失、版本更新、离线未缓存资源。消除工作区/资源组装的明显 N+1 查询。比较 1、5、20 个重复内置课程场景的响应体积、查询量和学习操作的本地写入范围，记录前后结果；验证课程选择、阅读、复习、笔记与离线恢复。

## P2-9：能力契约

建立后端能力和原生接入矩阵，明确教学单元、服务端计划/调整、笔记云同步、真实转写、手写、社区/社交的当前状态。可以增加向后兼容的能力接口与客户端解析；未接入能力不宣称可用，不新增产品入口或用演示结果冒充真实服务。现有功能保持不变。

## P2-10：维护性、配置与测试基线

围绕本轮改动抽出数据库、启动/缓存/同步、Worker 及明确的服务依赖，减少直接传入整个模块的依赖方式；不进行无关的机械拆文件。统一 OCR 实际使用的质量阈值和 Settings，修正文档与 Compose 的真实运行架构。补齐 CI 与可重复的测试命令；依赖仓库外 OCR 产物的测试须明确跳过或提供合理 fixture，不掩盖业务失败。处理涉及文件的 lint/type 错误。

## PostgreSQL 阶段 1：存储入口与迁移基础

采用受维护的 PostgreSQL 驱动与显式 schema 迁移机制（优先 SQLAlchemy Core、psycopg、Alembic；若使用更小的显式适配方案须说明依据）。添加 DATABASE_URL、有限连接池、配置验证、连接生命周期和启动健康检查。收敛 Native、Assessment、Community、Accounts、Social、Studio、OCR 的连接入口及事务边界，移除 PostgreSQL 路径中的 SQLite 专属语义。每请求/任务独立连接，不跨线程共享事务。不把开发环境建表逻辑当生产 schema 升级机制。

## PostgreSQL 阶段 2：业务持久化与一致性

迁移账户/会话/验证码与限流、书库/社交/Studio、工作区/资源/进度/复习、诊断/课程/事件。保留 ID、时间语义、JSON 结构、关联约束和必要索引。JSONB 是否采用按接口适配成本决定，不为了数据库迁移重做领域模型。

必须验证：revision 条件更新及 409；mutation/event 去重；FSRS 状态与事件原子提交；会话画像与事件原子提交；Studio 请求去重/额度预留；认证与资源隔离。明确自增 ID、冲突处理、大小写/排序、NULL、事务失败后回滚等跨数据库差异。质量检查缓存可继续本地存储，但说明其非权威缓存属性。

## PostgreSQL 阶段 3：任务与独立 Worker

OCR 持久化任务采用短事务领取（FOR UPDATE SKIP LOCKED）、租约、心跳、过期恢复及有界重试，长耗时工作在事务外。Studio 同样确保多 Worker 不重复领取、崩溃可恢复、旧租约执行者不能覆盖新结果。提供独立 Worker 命令及 API 禁用内嵌 Worker 的部署配置；保留本地单进程便捷模式。消除仅捕获 sqlite3.Error 的数据库异常处理。Compose 配置 PostgreSQL 健康检查、schema 初始化和 Worker，移除 Redis 服务及依赖。

## PostgreSQL 阶段 4：数据迁移与切换演练

实现显式命令：停写前提检查/操作提示、一致 SQLite 备份、目标 schema 迁移、按依赖顺序导入、计数/关键内容摘要/关联完整性校验、序列修正及报告。支持空目标安全导入和失败原子回滚；拒绝覆盖非空目标或要求明确安全的恢复流程，日志不输出秘密。

在隔离 PostgreSQL 中导入有代表性的账户、课程、进度、复习、聊天及任务数据，验证迁移前后读取与后续写入，保留原始文件。手册描述维护窗口、暂停 API 写入/Worker、备份签名密钥及文件产物、切换连接、检查后恢复服务。明确：接收 PostgreSQL 新写入后不能直接回切旧 SQLite，必须迁回增量或修复前进。

## 验收与执行顺序

1. 记录现有工作区和测试基线；完成数据库基础及兼容层。
2. 业务表、事务和迁移工具；真实 PostgreSQL 集成与并发测试。
3. 独立 Worker、任务恢复、Compose 与运行手册。
4. P2 离线/体积/能力/配置重构及针对性回归。
5. 子代理报告修改文件、已运行命令、测试结果和未完成项；主代理独立审核关键事务、认证缓存边界、任务租约及迁移失败路径。
6. 主代理运行后端测试、真实 PostgreSQL 测试、Swift 单元/集成及适用 UI 测试，记录基线问题与新增问题，修复后复测。真实 GPU/外部模型及生产切换未验证时必须明确说明，不用 mock 结果代替。

完成条件：上述范围有实现及可复现证据，无新增界面/功能回退；迁移工具通过隔离演练；Redis 不再是运行依赖。不能运行的环境验证列为未验证，不宣称通过。

## 本轮实施记录

实施代码已覆盖 P2-7/8/9/10 和 PostgreSQL 1–4 阶段；未提交既有 P1 修改，未执行正式迁移或部署。

- 统一 psycopg3/SQLite 入口、有限连接池、启动版本检查与 5 份显式 SQL migrations；43 张权威表有导入和 schema 清单完整性回归。保持文件存储与本机 iOS SQLite。
- Native revision/幂等/FSRS、Assessment 画像+事件、账户验证码/限流与 Studio 预算保持事务不变量；真实 PG 并发回归和原有 API 合同可用测试插件复用。
- OCR/Studio 使用短事务领取、心跳、过期恢复和有界重试；旧租约不能写数据库结果或覆盖文件产物。独立 Worker、API 禁用内嵌 Worker、跨进程持久心跳就绪状态、Compose schema/健康检查已提供，Redis 已从活动架构移除。
- 空目标停写迁移工具保留 SQLite 原文件与一致备份，验证 JSON、计数、摘要及外键，事务式修复序列。隔离演练包括账号、书库、工作区、进度、FSRS、诊断、课程、事件、Studio 笔记/版本、聊天与任务，并验证迁移后新写入和失败回滚；示例报告见 `validation/p2-migration.json`。
- 原生提前恢复已验证身份缓存，网络故障可离线写入，明确无效会话清理；加入默认端口/尾斜杠旧缓存兼容与不同端口隔离回归。网络恢复重新鉴权后自动同步。
- bootstrap 批量装配消除工作区/资源 N+1，原生请求 metadata 并按需获取版本正文；本机正文、资源进度与笔记独立持久化。可重复性能脚本为 `backend/scripts/benchmark_bootstrap.py`，样本见 `validation/p2-bootstrap.json`。冷启动首次仍需获取一份共享正文，不把 metadata 字节数当成总流量。
- 能力矩阵见 `NATIVE_CAPABILITIES.md`，操作手册见 `P2_POSTGRES_RUNBOOK.md`；未新增未接入能力的产品入口。OCR 不同评分模型分别通过 Settings 配置，保留原默认阈值。
- CI 定义已加入 SQLite/真实 PG 专测及既有合同复用、原生测试和首次 SPM 解析步骤；只在本机执行验证，没有声称远程 CI 已运行。

主代理独立审核、最终命令与结果由 `P2_POSTGRES_REVIEW.md` 记录。真实 GPU/MinerU、外部付费模型/真实 ASR、正式 SMTP、Docker Compose 实际启动和生产切换均不由隔离 fixture 或本机 PG 测试代替。
