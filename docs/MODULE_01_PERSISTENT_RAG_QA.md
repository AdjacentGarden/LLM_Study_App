# 模块 1 验收：持久化 RAG 与可核验教材答疑

## 模块边界

本模块把原先只存在于评测脚本中的检索能力迁移为 FastAPI 可复用服务，负责：加载持久化索引、BM25/向量融合、页级证据保护、交叉编码器重排、证据规划、DeepSeek 回答、逐字引用验证和教材外拒答。

正式接口：`POST /api/books/{book_id}/qa`。用户响应只包含答案、原子主张、页码和原文引语，不暴露 chunk id、向量分数或内部来源编号。

## 关键实现

- `rag/index.py`：索引清单、chunk、embedding 维度与唯一性校验；内存映射向量；BM25 + dense + RRF + reranker；页覆盖优先的证据预算。
- `rag/backends.py`：线程安全的 Transformer query encoder/reranker；GPU 显存门控；OOM 转换为可控服务错误。
- `rag/grounded_qa.py`：证据覆盖计划、答案生成、逐字引用验证、可选规划降级、校验失败重试。
- `llm/client.py`：OpenAI 兼容结构化调用；仅对 429、5xx、网络超时和截断 JSON 做受控重试，401 等明确客户端错误不盲目重试。
- `rag/service.py`：检索与生成编排、公开响应合同和分阶段延迟。
- `api/qa_dependency.py`：从环境配置构建持久服务，不把密钥写入代码。

## 自动化验证

全项目共 58 项测试通过。模块专项覆盖：

- 索引文件缺失、chunk 重复、embedding 形状和 encoder 维度不匹配；
- encoder NaN、reranker NaN、空问题和非法预算；
- 同页子块不能挤掉后续命中页；
- 英文/数字技术标识符的精确证据保护；
- 低分问题不调用模型；
- 伪造引语和未知来源被拒绝；
- 内部规划错误可安全降级，但最终答案引用标准不放宽；
- 截断 JSON 重试、401 不重试；
- GPU 显存不足在加载前被阻止；
- API 的 200/404/422/502/503 合同以及内部 ID 不泄漏。

Ruff、MyPy strict、前端生产构建和密钥扫描全部通过。

## 部署状态与基础设施边界

后端运行于 4090 服务器数据盘 `/data1/zhenghang/adaptive-book-ocr/app`，监听 `0.0.0.0:8100`。服务器本身当前没有公网出口，测试环境通过受控 SSH 反向代理访问 DeepSeek。此网络出口的永久化、高可用和断线监控属于最终部署模块；RAG/QA 代码在出口可用时已经通过全部模块门禁。
