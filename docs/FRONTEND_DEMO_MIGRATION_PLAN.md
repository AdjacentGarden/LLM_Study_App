# Demo 前端移植实施计划

制定日期：2026-09-27
状态：P0–P5 已由 GPT-6 Sol / max 子代理实施完成，并经主代理验收通过；2026-09-29 已在本地将原 Demo 页面与交互作为唯一默认前端、清理旧页面并接通当前业务。部署与发布后观察尚未执行。
目标：以 Demo 的界面、布局和交互为基础，替换当前项目的前端展示层，接通真实后端，并保留当前项目已有业务能力。

## 1. 范围与实施原则

| 项目 | 确定内容 |
| --- | --- |
| 来源 | `D:/code/study_app_demo` 当前工作树 |
| 目标 | `D:/code/LLM_Study_App/frontend`，必要接口在当前 `backend` 中补充 |
| 视觉基线 | Demo 的手机/平板布局、卡片、抽屉、阅读界面、动效和减弱动态效果支持 |
| 业务基线 | 当前项目的账号、教材、学习会话、主动诊断、个性化课程、学习记录、社区、社交、回访与 Studio |
| 产品名称 | 默认沿用当前项目的“云径 CloudPath”，将 Demo 中 BookCourse AI 等品牌文字统一替换 |

| 首版教材输入 | 单个 PDF；多文件合并、Office、图片等输入列入后续扩展 |

| 发布方式 | 沿用当前同源提供前端构建和 `/api` 的部署方式 |

用户最初授权使用 GPT-6 Sol / max 子代理实施 P0–P5，并由主代理验收；当时保留旧默认入口。2026-09-28 用户要求切换默认入口并删除旧前端，随后又要求完整搬运原 Demo 前端。现在 `frontend/src/demo` 保存 Demo 页面与样式，`frontend/src/demoPort` 将其接入当前业务，`/` 与 iPhone 模拟预览都加载这一实现；历史 Next 页面已清理。任务项仅在对应实现及验证完成后更新。最终检查结果与未配置外部服务的验证边界见 [FRONTEND_MIGRATION_ACCEPTANCE.md](./FRONTEND_MIGRATION_ACCEPTANCE.md)。

首版完成必须同时满足：Demo 的核心视觉与交互已迁入、真实学习流程可走通、当前已有功能未丢失、可恢复原界面。Demo 独有而后端尚未支持的增强功能单列，不与首版完成混为一谈。

不直接复制来源仓库的 `.env.local`、`node_modules`、`dist`、`.cache`、`tmp`、录屏产物、模型缓存或整套 Android 工程。来源仓库保持不变。

## 3. 目标结构与兼容方式

```text
Demo 页面、样式、动效 + 当前项目补充页面
                    ↓
            页面状态与业务用例
                    ↓
       独立 Repository 接口 + 数据转换
                    ↓
        当前 api 客户端 / transport
                    ↓
             当前 FastAPI 服务
```

建议在 `D:/code/LLM_Study_App/frontend/src` 内新增以下职责，不整体覆盖现有同名文件：

| 位置（相对于上面的绝对目录） | 职责 |
| --- | --- |
| `app/AppRoot.tsx` | 新应用入口、顶层 Provider 与身份重置 |
| `app/navigation.ts` | 页面、返回、弹层和刷新恢复；保留 Demo 导航状态机可复用部分 |
| `screens/` | 迁入的 Demo 页面与新增业务页面 |
| `components/ui/`、`layouts/`、`motion/` | 从 Demo 拆出的基础控件、布局、动效 |
| `services/contracts.ts` | 与演示类无关的 Repository 接口，按教材、课程、学习记录划分 |
| `services/http/` | 基于当前 API 客户端实现业务调用 |
| `services/mappers/` | 后端响应到页面展示模型的明确转换 |
| `state/` | 当前账号、教材、学习会话、课程版本和页面状态 |
| `types/viewModels.ts` | 页面模型，与现有后端 API 类型分离 |
| `styles/next/` | 新视觉系统；过渡期与旧样式分开加载 |

保留当前 `api/accounts.ts`、`api/client.ts`、`api/transport.ts`、`api/social.ts`、`api/retention.ts` 和 `api/learningStudio.ts`。保留现有 `types/api.ts` 作为当前协议依据，不能用 Demo 的同名类型覆盖。

过渡期曾使用两个互斥入口，新界面通过 `?ui=next` 预览，旧界面作为默认。2026-09-28 先切到 Next 入口；2026-09-29 按用户进一步要求改为原 Demo UI 的单一入口，删除旧页面和未使用的 Next 学习页面。设备预览在独立视口中加载同一应用，预览参数不改变账号权限。

本地切换现由 `frontend/src/main.tsx` 加载 `demoPort/DemoPortEntry.tsx`。旧入口已按用户要求删除；回退需恢复此前 Git 版本或上一前端构建，保留数据库、教材、索引和用户记录。

## 6. 接口适配与后端修改边界

下列现有接口由前端复用或组合；原文页 JSON 与 PNG 接口已附加实现，详见 [FRONTEND_MIGRATION_SOURCE_API.md](./FRONTEND_MIGRATION_SOURCE_API.md)。书架接口同时修正诊断就绪状态的动态读取。

| 业务 | 接口/模型依据 | 处理方式 |
| --- | --- | --- |
| 身份 | 现有 `/api/auth/*`、`/api/user/profile` | 复用；身份取自真实会话，不能依靠前端固定 user_id 建立权限 |
| 个人书架 | 现有 GET `/api/library` | 展示模型适配；按当前结构匹配的题库动态计算诊断就绪状态，不以公共 `/api/books` 列表替代 |
| 上传与解析 | 现有 `/api/books`、`bind-upload`、`process`、`status`、`structure`、`claim` | 前端业务编排；遇缺字段只作必要兼容扩展 |
| 学习前诊断 | 现有 `/api/interviews/start` 及 profile/next/respond/confirm | 保留多阶段流程和会话归属 |
| 个人课程 | 现有 `/api/interviews/{session_id}/courses/{chapter_id}` | 保留版本；按章节生成，不伪装成一次全书任务 |
| 练习与闪卡 | 现有 practice/flashcards 子接口 | 服务端评分/FSRS；稳定 event_id；不暴露题目私有答案 |
| QA | 现有 `/api/books/{book_id}/qa` | 单书、单问题；保留证据不足与引用层级 |
| 原文页 | 已新增 GET `/api/books/{book_id}/pages/{page_number}` 及同路径 `/image` | 返回页元数据、提取文字与受权限保护的 PNG；检查书籍权限、页码边界，区分 PDF/印刷页；按需渲染与有限缓存 |
| 新上传教材封面 | 现有 cover 能力主要面向已发布书 | 缺图可用通用封面；如扩展私人封面，复用原页生成并增加归属校验 |
| 笔记、社区、社交 | 现有 library/resources、library/notes、community 与 social 接口 | 保留资源 ID、帖子 ID、教材 ID 的区别 |
| 回访与 Studio | 现有 learning 与 studio 接口 | 保留任务、版本、能力状态、媒体与原始记录 |

新增后端能力优先采用附加接口/可选字段，保持旧前端能运行。前端换界面不触发教材重解析、数据库重建或学习记录清空。若实际需要数据库迁移，需另列增量方案和回退兼容性，不能作为复制页面的隐式步骤。

## 8. 验收方案

### 自动化验证

- 数据转换：BookStatus 状态和进度、Course 到页面、题型、引用、缺失字段、最终教材 ID。
- 身份与异步状态：A/B 账号切换、教材快速切换、过期请求返回、刷新恢复和旧缓存兼容。
- 写入行为：上传绑定、领取、练习/闪卡 event_id 去重、保存失败、超时后的状态核对。
- 构建：目标 TypeScript 和 Vite 构建；新增引用资源可用；正式入口不依赖演示仓库或浏览器模型 Key。
- 测试边界：演示仓库派生的“production harness”仍是测试替身，不能作为真实后端验收证据。

### 浏览器关键用例

| 用例 | 验证内容 |
| --- | --- |
| 新账号/空书架 | 登录、空态、上传入口，没有默认生物课程填充 |
| 已有账号恢复 | 原会话、教材、课程与记录在新界面可继续 |
| 真实上传 | 成功、失败、需复核、重试、刷新恢复和最终加入书架 |
| 跨学科选书 | 至少两本教材交替使用，封面、章节、问答引用、笔记和练习均不串书 |
| 个性化学习 | 诊断前置、画像确认、章节课程、服务端评分和课程更新 |
| 闪卡复习 | 正常评分、重试不重复、刷新后的到期时间和回访一致 |
| 社区/好友 | 两个独立身份发布、领取、加好友、聊天、分享；重复领取处理正确 |
| Studio | 笔迹/音频保存恢复、任务失败和确认步骤、整理版与原始内容并存、媒体可播放 |
| 故障恢复 | 断网、会话失效、403、409、服务超时、素材丢失均有明确可恢复状态 |
| 回退 | 恢复此前 Git 版本并重新构建静态前端后，账号、教材和学习记录仍可用；已不再提供 URL 切换旧界面 |

需要真实模型/邮件/OCR 的测试使用隔离测试账号和教材，按能力逐项记录“通过 / 失败 / 未执行”，避免对生产用户资料执行测试写入。邮件登录不能只凭演示验证码推断真实投递通过。

### 视觉与交互验收

- 以 Demo 代表页面为参考，确认主要布局、间距、排版、抽屉和动效一致；动态内容不同允许合理布局差异。
- 覆盖窄手机、常用手机、横屏、平板、桌面，检查长标题、长回答、空数据和多章节。
- 检查触摸滚动、闪卡横向手势、键盘弹出、安全区、弹层焦点恢复、返回和 reduced-motion。
- 原生 Android 单独测试，不以浏览器设备框截图代替真机结果。

## 9. 主要风险与处理

| 风险 | 处理 |
| --- | --- |
| 两套 CSS 冲突 | 旧样式与旧入口已删除；新版复用组件只加载 `styles/next/` 样式 |

| 长时间生成与真实失败 | 实际任务状态或请求状态驱动 UI；不以动画结束代表服务完成 |
