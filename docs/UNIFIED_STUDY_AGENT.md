# 云径 App 统一学习 Agent · 产品与技术方案

2026-11-03 · 交付范围为设计与验收规范。下列阶段描述目标实现；引用的代码用于定位现状。

用户可以从 App 的任意对话入口向同一个在线 Agent 提出请求。Agent 理解用户意图，读取必要的 App 数据，在同一会话内回答、执行操作或请用户选择。页面提供“这一章”“当前图片”“刚才那道题”等指代信息。对同一账号，所有页面提供相同的工具和权限。离线时统一显示「AI 助手需要联网」。

## 阶段一　统一会话、入口与任务执行

**入口改造。** 全局助手、课程内聊天、发现页、阅读器圈选、批注、附件讨论和「整理成笔记」统一提交消息。没有选课、教材或选区也可以发起任务。语音转写作为用户消息输入。普通聊天保存到历史；笔记批注使用独立的临时会话。

**历史名额。** 每账号可保存 6 个普通会话。首次发送才占用名额，已保存且当前选中的会话、已封存的只读会话均计入。已有 6 个或更多时，尝试在新普通会话中启动对话即弹窗「已达会话数上限，请删除无用历史会话」。提供历史管理入口，由用户选择并删除；降至 5 个或以下后才能开始新对话。升级前超额的存档同样保留，由用户处理。满额不影响续聊已有且未封存的会话。首次发送与名额检查必须原子执行，避免并发创建第 7 个。删除历史不会删除已经独立保存的学习产出。

**历史访问。** 用户可手动查找和查看自己的历史。Agent 只能读取当前会话的消息和附件，不能通过历史搜索、附件索引或旧笔记内嵌的消息跨会话取数。

**临时批注对话。** 用户可在本次批注对话中追问；关闭后不保存问答文本、消息附件副本或工具轨迹，不写入历史侧栏、笔记的 conversation 字段或可重放的服务端聊天存档，也不占 6 个名额。只保存用户在该会话中实际创建或编辑的产出物，如新笔记、闪卡、复习任务及其必要来源引用。再次打开批注时显示已保存的产出，不恢复聊天内容。已提交的业务写入用操作 ID 核对，操作回执不包含聊天原文。

**请求与执行。** 每次发送绑定账号、会话 ID、消息 ID 和发送时的页面快照。快照包含当时可用的课程、资源、章节、页码、选区、笔记、练习状态和附件引用。模型基于请求与实际工具结果决定下一步。工具注册表定义参数、执行位置、权限、返回值和失败状态。服务端验证账号与云端资源归属；客户端执行本机读取、截图、导航及本机写入。每个返回对象使用业务 ID，后续操作按 ID 定位。用户中途翻页或切换课程不改变已经确认的目标。

**协议迁移。** 为现有选区工具协议增加新版本，使书籍与选区成为可选上下文，支持多种证据、结构化操作和会话归属。保留旧存档的读取及已提交操作的核对路径。普通会话持久化步骤、工具调用、操作回执和用户选择；临时批注遵循上文的产出物保存规则。取消会停止后续步骤，已提交操作按原操作 ID 核对。断网不启动离线问答；联网后能区分“未提交”“已经完成”和“结果待核对”。

**验收。** 在未选课的首页开启对话，在阅读器开启另一段对话；两者均能查课程、讨论附件。在指定课程的阅读器保存笔记后重开，笔记仍在，临时批注聊天为空。切换账号不会显示前一账号的上下文或继续其待确认操作。

现状入口见 [普通会话分流](../frontend/Core/AssistantHistory.swift)、[阅读器](../frontend/Features/Notes/SourceReader.swift)、[现有手机端工具循环](../frontend/Core/AgentRuntime.swift)、[服务端模型网关](../backend/src/adaptive_learning/api/assistant_routes.py)。

## 阶段二　取消固定步数，显示上下文容量

**运行终止条件。** 移除客户端 8 步停止条件、服务端步骤序号上限、与步数相乘的结果数量上限，以及能力声明和响应中的固定最大步数。现有服务端另有每任务 12 次模型提交、累计 160,000 输入 tokens 及累计输出和时长预算。重设这些旧任务预算，避免形成等价的轮数上限，或在合法的长上下文请求发出前拦截。保留单次请求超时、提供方容量限制、用户取消、重复提交防护。遇到相同动作反复失败且没有新信息时，报告具体原因并让用户选择；达到某个步骤序号本身不构成失败。

**上下文口径。** 输入框旁显示例如「当前上下文 742K / 1M tokens」。默认窗口 1,000,000 tokens，停止接收新一轮对话的阈值为 **900,000 tokens（900K，默认窗口的 90%）**。1M 是 Agent API 的最低窗口要求。服务端在开始推理前校验有效配置；窗口不足 1M 时直接拒绝请求，客户端显示「API 错误：模型上下文窗口不足 1M」。不以较小窗口继续，也不更改 900K/1M 规则。分子取本次调用送入模型的系统指令、工具定义、会话历史、资料片段、工具结果和图像输入。发送前显示估算值及“约”，返回后用服务商可用的实际输入用量校正。缓存命中仍占上下文；同段历史被重复发送不跨调用累加。成本统计和上下文显示分别记录。

**长对话传输。** 当前协议存在请求体长度限制，手机还会截短单条工具结果。仅提高模型窗口无法发挥 1M 容量。普通会话历史按消息保存，客户端增量提交新消息和回执，服务端按会话组装本次模型输入；大文件与图片使用受权限约束的资源引用。完整目录和文档保存在数据源中，模型可按标识继续取后续内容。工具结果必须标出是否完整，禁止静默截断。每次调用预留输出容量；达到实际服务容量时清楚提示原因。

**会话容量状态。** 普通会话在存档中持久化容量状态、触发用量、正在收尾的任务 ID 和原因；前后端均检查。达到阈值后一旦锁定，即使后续模型输入变小也不重新开放。

| 条件 | 执行与界面 |
|---|---|
| 小于 900,000 tokens | 正常接收新消息。 |
| 达到或超过 900,000，当前没有任务 | 立即归为只读历史，在对话页弹窗，唯一操作为「新建对话」。 |
| 已有任务执行中，达到 900,000 且小于 1,000,000 | 禁止发起新一轮；原任务可以继续取证、执行工具、接受针对本任务的必要选择并写回结果。完成、取消或失败后弹窗，唯一操作为「新建对话」。等待用户确认不能自动视为同意。 |
| 任务还未完成，达到 1,000,000（1M） | 立即在对话页弹窗，唯一操作为「新建对话」。不再发起模型调用或启动后续动作。只核对已提交操作并记录回执；在历史里分别标出已完成、未执行和待核对的部分。发起调用前若预计将越过有效容量，应提前拦截，不发送已知无法容纳的请求。 |

**阈值与名额同时触发。** 容量弹窗仍只有「新建对话」。若当时已有 6 个历史会话，启动新普通对话前显示名额弹窗并进入历史管理；删除前不创建记录、不发送请求，原封存会话维持只读。临时批注达到容量阈值同样停止新回合，但结束后仅保留产出物，不生成只读历史。

**普通会话重开与恢复。** 再打开已封存会话，保留聊天内容、工具结果和状态，常驻提示「此对话已达到上下文上限，无法继续对话。请新建对话。」禁用发送、语音、附件发送和重试入口，服务端也拒绝新回合。新建会话独立计数，不携带原历史。任务运行中关闭浮层或重启，不会抹去待收尾或只读状态。

**验收。** 覆盖 899,999、900,000、999,999、1,000,000 和单次跨越两道阈值；覆盖空闲、执行中、等待用户、网络中断及重启。验证收尾期间无新回合、到 1M 未完成仍立即提示、只读会话不能通过旧的重试入口绕过限制。不同调用累计消耗达阈值而当前上下文未达时不触发。另验证长任务能超过旧的 12 次提交限制。

现状限制见 [客户端任务模型](../frontend/Core/AgentRun.swift)、[运行预算](../backend/src/adaptive_learning/assistant_ledger.py)、[协议与请求校验](../backend/src/adaptive_learning/api/assistant_routes.py)。

## 阶段三　提供完整课程目录与发现页检索

| 能力 | 技术行为 | 结果要求 |
|---|---|---|
| 查看所有已保存课程 | 合并当前账号在 App 中可见的本地与云端课程，按真实身份去重，保留同名的不同课程。列出准备中课程及其状态。 | 返回课程 ID、名称、资料状态和总数。用户问“全部”时遍历所有页。 |
| 查看任意课程全部章节 | 按课程 ID 和资源 ID 批量取目录，保留一本或多本教材的层级、顺序和原始标题。 | 区分完整、无章节、未生成和读取失败。大目录可折叠或分段阅读。 |
| 搜索、汇总发现页 | 复用发现页实际目录合并与可见性规则，按标题、学科、年级、版本等现有字段匹配，并与已保存课程比对。 | 返回真实目录项、来源、已保存状态与可打开目标。资料未提供的字段留空。 |
| 获取课程 | 对已选中的目录 ID 调用现有获取流程，重复操作复用已有结果。 | 分别报告已加入课程、原文件下载中或已下载，按实际回执展示。 |

对于“我有哪些课程，各有哪些章节”，先读取完整课程列表，再批量取得每门课的目录。执行层处理分页，模型可以按课程继续展开。若只成功读取三门中的两门，列出已取得的两门并标出失败项；不能把部分结果表述为全部。对于“找一门我还没有的课”，先比对两个目录，确认用户选择的目标后跳到获取页面。打开页面和实际下载使用不同动作。

**验收。** 使用超过一页的目录、两门同名课程和一门尚未生成章节的课程，与用户界面逐项核对。搜索后撤回的发现页课程应报告无法获取。

可复用 [服务端目录汇总](../backend/src/adaptive_learning/native_catalog.py)、[课程目录与导入路由](../backend/src/adaptive_learning/api/native_routes.py)、[客户端发现页目录合并](../frontend/Core/CloudBootstrap.swift)。

## 阶段四　按需读取课程、附件和学习记录

**图文读取。** 全部已保存课程中的文字和图片均应可通过工具定位。Agent 先查目录、索引、章节、图注或相关段落，再选择原文、原图、页面渲染图或圈选区域进入模型上下文。没有 OCR 或图注的插图仍应能从章节和页序找到。用户明确引用附件时按会话内附件 ID 取文件和页码。模型已选定支持多模态，需实际接通图像输入并统计其上下文用量。对每类实际支持的课程和附件格式，以原图能否取出、模型能否收到、出处能否返回三项验收。

**学习数据读取。** 支持检索课程、笔记、批注、计划、复习任务、闪卡、已提交作答和学习进度。工具接受课程、日期、关键词和对象 ID 等筛选条件。所有读取遵守账号权限；按真实资源返回“没有匹配记录”“尚未就绪”或明确错误。回答和笔记中的教材、图片、附件、学习记录分别保存其来源类型、对象 ID、版本及页码或定位信息。引用由执行层核对，普通知识补充与引文分开显示。

**章节练习规则。** Agent 可以解释教材概念、讨论附件和复盘已提交的作答。对当前待作答的章节题，不提供答案、代填或提交。练习状态来自业务数据，在使用截图、附件和切换入口时同样适用。复盘只使用真实存在的答案、分数、反馈和尝试记录。统计“错误次数”和“做错过的不同题目数”时分别计数；未记录错误原因时，不能把推测写成用户的真实思路。

**验收。** 用两门课中只有查看图像才能区分的插图做比较，核对实际发送的图片及出处。用包含重复尝试的已提交记录生成错题统计并创建闪卡。对同一待作答题在练习页和全局助手验证相同边界。

现有 [附件提取](../frontend/Core/AssistantAttachment.swift)、[教材证据核验](../backend/src/adaptive_learning/rag/grounded_qa.py) 和 [按资源读取作答记录](../backend/src/adaptive_learning/api/native_routes.py) 可复用。内置目录课的记录接口有课程类型限制，其他课程须对接各自的实际记录源。

## 阶段五　截图与全 App 页面导航

**截图。** 新增“查看当前界面”工具，客户端捕获调用时本 App 的实际可见界面，返回截图 ID、页面、业务对象、时间和图像。支持两种捕获目标：业务页面（临时排除助手浮层，保留当前滚动位置与选区）以及含助手在内的完整界面。前者用于“解释我正在看的这张图”，后者用于“对话框中这个按钮有什么用”。若页面已切换，返回实际捕获对象并重新核对指代。进度卡可展开预览送给模型的截图。截图只描述可见区域；需要完整章节时调用资料读取工具。

**导航。** 以 App 用户实际可到达的界面建立导航注册表。每个目标声明页面类型、可选或必需的课程/章节/记录 ID、入口条件及到达验证。至少覆盖首页、课程库、发现和获取页、任意课程与章节的学习页、教材阅读页、闪卡与复习、练习入口、学习笔记、做题本/错题详情和学习计划。其他主要用户页面按实际路由纳入同一清单。页面只有列表入口而尚不能定位记录时，补齐详情或选中定位。验收时以 App 主要页面清单逐项核对，不能用“已打开列表”代替“已定位指定对象”。

**交互。** 用户明确说“打开这章的闪卡”即可导航；只要求推荐课程时，展示匹配结果并询问要不要跳转。确认绑定稳定目标 ID。App 确认页面和对象都已就绪后返回已到达。目标缺失、无权限或尚未生成时说明具体状态。

**验收。** 从笔记页打开任意课程指定章节，截取业务页；再从该对话打开刚创建的闪卡和上次作答记录。逐次断言实际页面与对象。切页期间的截图不能被描述为原页面。

## 阶段六　写入学习数据及关联删除

| 操作 | 执行规则 |
|---|---|
| 新建、编辑、打开、删除笔记 | 新建返回笔记 ID 与版本，支持打开刚保存的笔记。编辑指定已有笔记并检查版本冲突。删除时显示目标名称并确认。 |
| 创建、调整学习计划 | 将日期、任务和课程写入真实计划；只调整请求涉及的范围。写入后能打开指定日期核对。 |
| 创建复习任务或闪卡 | 可从教材、附件或已提交错题生成；返回可打开的任务或卡片 ID。“建议如何复习”只产生建议，“加入我的计划”才写入。 |
| 下载或移除课程 | 使用课程的真实身份执行。移除确认卡展示课程名称及关联笔记、闪卡、复习任务和学习记录各自的实际数量。 |

**按课程隔离同一本教材上的原文笔记与批注。**

1. **保存归属。** 从无指定课程的入口打开资料，可以对话；若要求写笔记，手动入口和 Agent 均提示「无指定课程，无法进行笔记撰写」，并在创建草稿或调用写入服务前终止。即使资料只匹配一门课程也不自动认领。用户从具体课程重新打开资料后才可撰写。「未归属笔记」只接纳迁移中无法判定归属的旧原文记录。 在笔记锚点、阅读器入口、Agent 原文选区和写入回执中传递课程教材关系的稳定 ID（`course_resource_id`），同时保存原文位置（页码、选区或已有坐标）。两门课程可共用教材文件，各自的课程资源 ID 不同。线上复用工作区资源主键；客户端 `Course.resourceIDs` 当前映射的是教材 ID，不能直接填入此字段。纯本地课程需要为课程与教材的关联保留稳定 ID，本地转云时用持久映射保持笔记归属。
2. **按归属读取。** 在当前账号内严格使用“课程资源 ID + 页码”筛选原文页面。课程笔记列表、章节笔记、手写、文字、语音批注和 Agent 原文查询使用同一归属规则。移除“旧笔记 courseID 为空也可匹配”的分支。按笔记 ID 打开原文时同时定位课程资源。
3. **旧数据迁移。** 仅当现有课程、教材和可靠历史关联能唯一确定资源时自动补 ID；无法唯一确定的原文笔记进入「未归属笔记」，不叠加到任何课程页面。用户在未归属列表选择对应教材所在的课程后，持久化归属并保留原文位置。迁移可重复执行，不覆盖用户已指定的归属。普通无原文锚点的独立笔记不因这次迁移而被当作旧批注。
4. **Agent 与删除。** Agent 创建、查找、编辑原文笔记时使用相同的资源 ID；删除课程之前先固定该课程的资源 ID 集合，在账号内据此清理其原文笔记。不以教材文件 ID 批量删除，不清理其他课程和未归属笔记。其余明确归属该课程的学习数据照既定规则清理。
5. **验收。** A、B 两门课使用同一 PDF 同一页，各写一条批注，分别检查原文页、章节列表、Agent 检索与打开。迁移一条唯一匹配和一条有歧义的旧笔记；将后者手动归到 B。删除 A 并重新同步，B 的两条记录与仍未分配的记录应保留。

现状核对见 [阅读器筛选与锚点](../frontend/Features/Notes/SourceReader.swift)、[课程笔记筛选](../frontend/Core/AppStore.swift)、[章节笔记筛选](../frontend/Features/Notes/NotesViews.swift)、[云端课程映射](../frontend/Core/CloudStore.swift)、[Agent 写入校验](../frontend/Core/NoteMutationStore.swift)。

**移除语义已确定。** 用户确认后，直接删除目标课程及其关联的笔记、闪卡、复习任务和学习记录。取消则不产生变更。不同课程即便同名或共用教材，也不得误删其他课程的数据。手动移除与 Agent 移除调用同一业务操作。对当前账号和课程生成影响清单，确认绑定对象、范围和版本；确认前范围变化则刷新清单。云端事务清理其负责的数据，本机清理存档与缓存；跨端操作保留可恢复回执，重新同步不应复活已删记录。

**写入通用约束。** 使用稳定操作 ID 防止断线重试造成重复写入。对象、参数、操作结果和错误均由执行层校验。部分成功时展示已完成动作，未取得写入回执时保留待核对状态。存在更高版本的用户手动编辑时不得静默覆盖。

**验收。** 新建、编辑后重启，确认对象可见且版本正确。对两门共享教材的同名课程移除其中一门，核对四类计数、取消、确认、中断恢复及重新登录后的结果。当前 [本地移除入口](../frontend/Core/AppStore.swift) 和 [云端工作区删除](../backend/src/adaptive_learning/native.py) 本身不足以证明这四类跨端数据已完整清理。

## 阶段七　把进度、工具调用和操作确认放进对话消息

每条 Agent 回复可展开查看操作记录。执行中展示简短的处理概要，以及由运行事件产生的真实进度。模型的内部推理不作为用户界面内容。一般知识回答无需人为插入工具步骤。

| 消息状态 | 展示行为 |
|---|---|
| 开始、读取中 | “正在查看已保存课程”。取得总量后才能显示“已读取 2/3 门课程目录”。 |
| 等待用户 | 在原消息内显示选项、对象和影响范围。例如「打开下载页」「暂不跳转」或「移除课程并删除关联数据」。 |
| 操作完成 | 显示结果和可打开的目标；折叠保留读取来源、截图、工具动作及回执。确有回执才显示“已保存”“已删除”“已到达”。 |
| 部分失败、结果未知 | 标出具体失败项或正在核对的操作。仅重试仍需执行的动作，普通会话回到旧消息可见最新状态，临时批注仅在当前对话展示。 |

在现有 [助手浮层](../frontend/App/GlobalAssistantOverlay.swift) 和 [输入框](../frontend/App/AssistantComposer.swift) 接入消息级运行状态和上下文指示。运行卡绑定会话与消息，不依赖助手浮层持续打开。

## 端到端交付条件

1. 从任意入口执行“列出所有课程及各章”，与课程库完整核对，包括未就绪和部分失败的情况。
2. 从发现页以外的入口搜索未保存课程，用户确认后到达正确获取页；另行执行下载并核对回执。
3. 从笔记页跨课程找图文，截取实际界面，对照附件回答，保存带出处的笔记，随后打开并编辑该笔记。
4. 从已提交的错题生成闪卡与复习任务，调整指定日期的计划，导航到正确对象。待作答章节题的答案和提交操作始终不开放。
5. 超过旧步数和提交次数仍可完成有效任务；按当前上下文在 **900K** 锁定新回合并允许在途任务收尾，**1M** 强制封存；重新进入只读历史时显示提示。离线展示不可用。
6. 移除课程后验证四类数据在本机、云端和再次同步后均已清除，其他课程保持完整。
7. 验证每账号的历史对话上限为 6；用户可手动查看所保留的历史，Agent 不能通过会话工具、旧附件或笔记附带的对话读取其他会话。
8. 验证共享教材的资源隔离、旧笔记自动迁移、未归属笔记手动认领，以及删除其中一门课后的隔离效果。

9. 已有 5 个普通会话时可创建第 6 个；已有 6 个或升级前超过 6 个时，首次发送被拦截，没有模型调用，既有记录不被自动移除。封存后从容量弹窗新建同样受限。手动删至 5 个后可正常开始。
10. 在指定课程的临时批注中生成笔记，关闭并重启后，历史条数不变，笔记、来源和课程归属都在，聊天内容不可恢复。从无课程入口打开同一资料时，手动和 Agent 写笔记都显示指定提示，没有新增记录。
11. 使用窗口不足 1M 的 API 配置发起请求，服务端拒绝推理，客户端显示 API 错误；窗口满足要求时再执行 900K/1M 边界用例。

## 工程验证

**需工程验证，无需重新决定产品需求。** 核查所有资料格式的原图读取、各类课程的已提交记录字段与归属、所有主要页面的对象定位，以及笔记附件与操作回执的独立引用关系。历史清理不能误删仍被笔记引用的文件；若旧闪卡、任务或学习记录缺少足够归属证据，单独列出数量与可恢复关联，不能直接套用仅针对原文笔记的认领规则。另需验证模型用量回执与发送前估算在图像请求上的差异。
