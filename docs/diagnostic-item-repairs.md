# 诊断题逐题自动修订

生产 API 创建 `DiagnosticItemGenerator` 时使用 `validation_retries=None`，通过教材准备队列持续推进；审核拒绝没有次数上限。有限次数参数保留给旧协议回归及离线调用，不用于生产教材准备。

每次队列调度对每个待处理知识点最多执行一轮生成和独立审核。每个模型请求只包含一道题；原认知目标及原文依据随该题传递。已通过题目独立保存，不进入后续生成请求，已通过的旧版本完整章节也直接复用。单题反复拒绝时每三轮切换一次重新设计策略，不删除已通过结果。

审核意见与上版候选题持久保存在 `diagnostic_item_repairs`；保存反馈和结束本次提交使用同一事务，并检查提交令牌。已通过内容继续使用原有审批摘要与来源指纹校验。修改来源、认知目标或审核协议会使相应审批失效。

普通审核拒绝后，教材准备状态保持 `queued`、阶段为 `diagnostics`、检查点为 `2`。等待时间依次为 5、10、20、40、80、120 秒，此后保持 120 秒；次数持续增加，不会耗尽。等待期间释放工作线程，其他教材可以运行。GET 进度接口只读，不会重新提交推理。

进度接口增加可选 `message`、`diagnostics_completed`、`diagnostics_total` 字段。只有全部要求的题目通过，才保存完整题库并标记教材就绪。部分审批内容不会被提前发布为完整题库。

审核优先检查答案正确、唯一、原文支持、清晰可答及指定认知目标。允许忠实改写、合理长度差异和正确旧文字复用；不再以“旧选项没有全部替换”为由机械拒绝。

明确的模型限流、服务暂不可用或尚未发送成功的请求自动等待恢复。审核调用尚未发送成功时保留候选题，只重试审核。无响应且无法确认提交结果的调用仍保留原有提交隔离，不能假定审核拒绝并盲目重复付费调用；此类实际通信异常仍可使用显式恢复入口。

`POST /api/books/{book_id}/prepare/cancel` 暂停后续工作，保留已有检查点；已经发出的模型请求可能完成，但不会再进入下一轮。通过原 `POST /prepare?retry=true` 恢复。两个接口均要求原有教材归属及会话校验。直接调用 `POST /diagnostics` 时，尚未完成的一轮返回 HTTP 202，包含进度和 `Retry-After`，而不是审核失败的 502。

SQLite 启动时兼容升级原队列表。PostgreSQL 部署前须通过现有迁移流程应用第 008 号迁移，增加逐题修订表及准备队列的重试时间、进度详情字段。旧版本已标记失败的任务需通过现有“继续教材准备”入口恢复一次；新产生的普通审核拒绝会自动持续处理。
