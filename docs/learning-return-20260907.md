# 长期记忆与阅读疑问回访 · 2026-09-07

## 用户入口

没有新增底部导航。学习页在下一课推荐下嵌入「不只今天记得」；已有学习档案时展示安排，尚未开始时仅说明如何开启，不伪造到期任务。原文摘录下有「这段还没懂，留待回访」，答疑结果或失败提示后有「还没懂，记下来」。按钮位于聊天滚动区，不挤占底部输入框。

### 记忆回访

- 从已有章节闪卡与 FSRS-6 状态生成到期队列，不重新生成整章，也不调用模型来计算日期。
- 进入回访先展示卡片题面，翻面后选择回忆程度。保存使用已有复习接口与幂等事件 ID，继续更新 FSRS 排程和画像。
- 统计「间隔至少 24 小时」的回访，以及「间隔至少 7×24 小时后自评记得」的次数。首次学习、当天重复翻卡不算七天回访。
- 历史记录与下一次日期来自服务器；自评不等同于客观测验验证，不展示虚构掌握率。
- 当前第一版复用原闪卡进行回忆，并未增加 LLM 变式题生成或客观评分。间隔由 FSRS 决定，不强制所有卡片都在第七天复习。

### 疑问回访

- 保存问题、教材、章节、页码、原文线索。账号绑定前后使用既有所有者体系；不公开到社区或好友。
- 初次保存安排三天后回访；重回明确关联的章节时也会提供轻提示。答疑依据的页码用于定位对应章节，不把无依据问题强行关联到某章。
- 「7 天后再看」会在这段时间抑制章节提示；「我已经理解了」可附一句个人理解，已解决记录仍保留；可以重新打开。
- 「继续问」选中关联教材并带回原问题，用户补充后发送，不自动消耗模型调用。
- 当前是 App 内提示，不是系统推送、后台定时通知或跨章节语义推荐。关联依据为显式章节和引用页码，不声称已实现自动发现所有相关章节。

## 后端与数据

`api/retention_routes.py` 通过现有社区路由的访问依赖接入：

- `GET/POST /api/learning/doubts`
- `POST /api/learning/doubts/{id}`：resolve / reopen / snooze
- `GET /api/learning/memory/{session_id}`

`community.sqlite3` 新增 `reading_doubts` 表与索引。相同所有者、教材、规范化问题通过唯一键去重；每书每人最多 200 条。写入使用 SQLite 事务，验证书架所有权与同源请求；不可修改他人疑问。移出书架后保留数据但不可访问，恢复教材后可以找回。

记忆队列读取既有 `assessments.sqlite3` 中的课程、学习事件和 FSRS 状态，事件查询仅取时间、卡片 ID 与评分，不加载整份历史画像到前端。客户端时间不能操纵服务端到期计算。账号/教材切换时，已卸载组件的迟到复习结果不会写进新档案。

### 测试边界

七天统计通过独立测试访客的历史时间样本验证，并未真的等待七天，也不是长期学习效果实验证据。测试脚本只允许修改十分钟内创建、零修订、`return-e2e-` 前缀的专用档案，不修改现有个人档案。章节内容来自已解析的教材；测试中的章节打开响应使用专用课程样本，避免为 UI 定位反复生成新课程。复习写入、疑问 CRUD、持久化、隔离和答疑均走实际 4090 接口。

此测试保留隔离的测试访客数据，不把测试成绩填入用户当前档案，也不发送邮件或短信。实际 iOS 软键盘、系统通知和长期真人学习效果不在此次验收范围内。
