# 课程内容的独立生成与修正

课程中的讲解、闪卡、练习、导入、总结、各例题和检查题分别拥有草稿、审核结果、
重试时间、失败计数和版本。一次队列执行处理所有已到期组件；单项内容、格式或服务错误
由该组件保存并退避，不取消其他组件的生成和审核，也不清空整份章节稿。

写作前通过章节来源检索为该组件准备证据包，包含原文、来源 ID、页码、相邻条件与
具体修复任务。通常初始选择 8 段，随失败扩大范围；导入与总结使用更广的章节概览。
检索结果只作为候选，不能自动获得事实批准。全章证据仍供原有事实审核和范围核查使用。
修复引用时明确修改当前组件自己的 source_ids，章节阅读目录不能替代本题引用。

首稿被拒后先局部修正；连续两轮修正失败，下一轮必须完整重新设计被拒题目。
事实、计算、题设、引用、评分、格式、无实际修改及确认的服务失败采用相同计数规则。
重新设计解除旧的 rubric_only 编辑限制，重构题设或实际问项并同步重做答案、评分和引用。
只换数字、措辞或顺序不算有效重设；程序检查题目变化，独立教师进一步核验实质变化。
原文、事实与教学拒绝意见持续保留，格式或未修改错误不能覆盖它们；重设时提供失败设计历史，避免循环返回同一问法。
讲解、导入和总结采用相应的完整重写。重设失败后开始下一轮修正周期。

每次模型提交属于明确的组件。结果不确定时保留原请求，并仅暂停对应组件；同轮其他
组件继续推进。确认失败或收到无效响应后才允许安全的新提交，轮询不会增加失败计数。
若已知输入的旧审核在本地结束且响应不可恢复，经后台恢复核对后将其保留为 retired_revision，
永久禁止重放该请求；废弃旧稿并强制生成实质不同的新题，再做全套审核。尚在运行的请求不能退休。
完整返回但被判为无效的修正响应失效处理，新的修正轮次携带独立请求标识。

事实审核沿用逐断言、引用原文、适用条件及范围矩阵校验。组件草稿不能直接批准；
每项都需要事实与独立教师审核，练习还需评分公平性审核。有效事实证明按内容、原文、
范围规划和审核身份的精确指纹复用。最终汇总全部必需组件后检查整章覆盖、重复和矛盾；
发现问题仅重新安排涉及组件。整章通过全部必需审核后才发布，不分批开放未完成课程。

teaching_course_units.work_json 保存组件状态、版本历史、证据定位反馈及批准记录。
teaching_course_submissions.unit_id 将请求恢复限定到单个组件。
teaching_course_epochs 为明确要求的从零生成创建新批次，隔离旧草稿、审核证明和模型响应。
旧记录留作归档，不导入新批次；诊断题、已有课程及学习历史不受影响。

PostgreSQL 通过 python -m adaptive_learning.migrate schema 显式升级到版本 10。
SQLite 在原队列库增量创建相同字段与批次表。前端沿用原任务查询显示实际完成数。
